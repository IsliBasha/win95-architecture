Four architectural layers
Context
WindowStackProvider owns global state: an ordered array (z-index = position in array) + three Sets/Maps for hidden, closed, maximized.
Components
Thin wrappers. Read context, render JSX. No game logic, geometry, or API calls inline.
lib/
Pure functions — no DOM access. Testable in isolation: computeResize, minesweeper, snake, bootChime.
hooks/
Behavioral reuse — useClock, useInactivity, useWindowPosition, useIconPosition, useInView.

export function computeResize(edge, start, delta) {
  const w = Math.max(MIN_W, start.w + delta.x)
  return { width: w, height: h }
} // tested without mounting any React component
Why does this matter?
"Keep logic that doesn't need the DOM out of components and into lib/" — Isli Basha
→ Anyone can test it — no browser needed. Just data in, data out. Like a math function.
→ Team worked in parallel — Isli built the window shell while Sidrit wrote game logic. Neither blocked the other.
→ Same input = same output, always — no hidden state, no surprise bugs that only appear when you click in a certain order
→ Portable — the game logic works outside React without any changes

Snake · The stale closure trap
// setInterval closes over 'game' at creation time
// 'game' is always the initial value — the snake never moves

// WRONG:
setGame(tick(game)) // stale — uses first 'game' forever

// RIGHT: functional updater — React gives you latest state
setGame(g => tick(g)) // always fresh
→ All logic tested before any JSX — minesweeper, snake, and direction rules were done and green before the first component was opened
→ Components are thin wrappers: read lib state, render grid, handle keypress
→ His lib files drive most of the 172 tests in the suite
